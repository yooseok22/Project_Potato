# 감자 전분 가공 시스템 작업 계획

> 이 문서는 기존 임시 모형·실외 건조 테스트의 기록이다. 2026-10-13에 새 프랍 교체, 애니메이션 연결, 재배기 위 건조를 구현했다. 현재 동작과 검증 결과는 [PotatoStarchPropAnimationPlan.md](PotatoStarchPropAnimationPlan.md)를 따른다. 아래의 애니메이션 미사용·프랍 분석 제외·실외 건조·고정 5초 가공 규칙은 현재 구현에서 대체되었다.

## 1. 목표와 현재 확정 범위

감자를 믹서기로 분쇄하고, 체 통에서 물을 뺀 뒤, 젖은 전분이 담긴 건조 틀을 실외에서 말려 감자 전분을 만드는 플레이 흐름을 구현한다.

이번 시스템의 기본 흐름은 다음과 같다.

```text
감자 4개 소비 로그 출력(실제 인벤토리 차감 없음)
  → 믹서기 분쇄
  → 믹서기 들기
  → 체 통에 1회분 붓기
  → 믹서기를 제자리에 놓기
  → 위 과정을 체 통 5/5까지 반복
  → 5초 동안 물 빼기
  → 젖은 전분 건조 틀 꺼내기
  → 실외 바닥의 원하는 위치에 놓기
  → 150초 건조
  → 감자 전분 팩 5개 완성 로그 출력
```

현재 요구사항을 그대로 계산하면 체 통 1회 완성에는 감자 20개와 믹서기 작업 5회가 필요하다.

## 2. 프로젝트에서 재사용할 기반

| 기존 요소 | 재사용 방법 |
| --- | --- |
| `IPlayerInteractable` / `PlayerInteractionController` | 플레이어 시선 중앙의 대상과 `[E]` 상호작용, 상황별 안내 문구 표시 |
| `PlayerItemController.TryHoldInHands` | 믹서기 통과 건조 틀을 손 슬롯에 장착 |
| `IPlayerHeldItem` | 운반 중인 설비 부품을 손 아이템으로 표현 |
| `PlayerActionBlocker` | 분쇄 시작 입력 중복, 저장/메뉴 등과의 입력 충돌 방지 |
| `WorldClock` | 분쇄·물 빠짐·건조 진행 시간의 기준, 일시정지·배속·시간 건너뛰기 대응 |
| `SaveGameController` / `ISaveSection` | 정식 구현 단계에서 설비 진행 상태와 남은 시간 저장 확장 |
| `InteractionOutline` | 상호작용 가능한 믹서기, 체 통, 건조 틀 강조 |

프랍은 `Assets/Fbx/Food Processing`에 있으며 용도는 다음과 같다.

- `Potato Millionaire Starch Pack.fbx`: 전분 포장
- `Potato Millionaire Strach Blender 1.fbx`: 믹서기
- `Potato Millionaire Strach Maker 1.fbx`: 감자 전분 설비

위 파일들은 프랍이므로 이번 테스트 로직에서는 구조, 피벗, 애니메이션을 다루지 않는다. 파일명의 `Strach` 표기도 원본 그대로 유지한다.

## 3. 시간과 용량 규칙

### 확정된 값

| 항목 | 값 |
| --- | ---: |
| 믹서기 1회 감자 소비량 | 4개 |
| 체 통 최대 용량 | 5회분 = 감자 20개 |
| 믹서기 1회 분쇄 시간 | 5초 |
| 물 빼기 시간 | 5초 |
| 건조 시간 | 150초 |

### 확정된 총 소요 시간

```text
분쇄 5회 × 5초 = 25초
물 빼기 = 5초
건조 = 150초
순수 자동 진행 시간 = 180초
```

감자 20개를 4개씩 처리하므로 분쇄는 총 5회이다. 최초의 3분 목표를 맞추기 위해 물 빼기 시간은 테스트 값 5초로 둔다. 세 시간 값은 Inspector에서 조정할 수 있게 하되 기본값은 각각 5초, 5초, 150초로 고정한다. 플레이어가 믹서기와 건조 틀을 옮기고 `[E]`로 상호작용하는 시간은 180초에 포함하지 않는다.

모든 시간은 기본적으로 `WorldClock.ElapsedSeconds` 기준의 게임 시간으로 처리한다. 일시정지 중에는 멈추고, 게임 배속과 명시적인 시간 건너뛰기는 반영한다. 이번 테스트에는 Animator를 사용하지 않는다. 시간 건너뛰기로 종료 시각을 넘으면 즉시 다음 상태로 전환하고 해당 완료 로그를 출력한다.

## 4. 상태 설계

상태를 여러 `bool` 조합으로 관리하지 않고 enum 기반 상태 기계로 관리한다. 그래야 중복 투입, 진행 중 들기, 체 통 초과 투입 같은 잘못된 전이를 차단하기 쉽다.

### 4.1 믹서기

```csharp
public enum BlenderState
{
    DockedEmpty,
    Grinding,
    GroundReady,
    CarriedFull,
    CarriedEmpty
}
```

| 현재 상태 | `[E]` 동작 | 다음 상태 |
| --- | --- | --- |
| `DockedEmpty` | 감자 4개 소비 로그를 출력하고 분쇄 시작 | `Grinding` |
| `Grinding` | 상호작용 불가, 남은 시간만 표시 | 시간 종료 후 `GroundReady` |
| `GroundReady` | 믹서기 통 들기 | `CarriedFull` |
| `CarriedFull` + 체 통 조준 | 체 통에 1회분 붓기 | `CarriedEmpty` |
| `CarriedEmpty` + 원래 자리 조준 | 믹서기 통 장착 | `DockedEmpty` |

테스트 단계 추가 규칙:

- 실제 감자 보유 여부는 검사하지 않는다.
- 실제 인벤토리에서 감자를 차감하지 않고 `[PotatoStarch] 감자 4개 소비` 로그만 출력한다.
- 체 통이 가득 찼거나 물 빠짐 중이면 붓지 않는다.
- 가득 찬 믹서기는 원래 자리에 놓지 못하게 하여 내용물 유실을 막는다.
- 믹서기 통은 일반 아이템처럼 던지지 못한다. 기본안에서는 지정 대상에만 `[E]`로 붓거나 복귀할 수 있다.
- 분쇄 시작 후 5초가 지나면 애니메이션 없이 `GroundReady`로 전환하고 완료 로그를 출력한다.

### 4.2 체 통과 젖은 전분

```csharp
public enum SieveState
{
    Filling,
    Draining,
    WetStarchReady,
    TrayRemoved
}
```

| 현재 상태 | 동작 |
| --- | --- |
| `Filling` | 믹서기 1회분을 받을 때마다 `fillCount`를 1 증가 |
| `fillCount == 5` | 추가 투입을 잠그고 자동으로 5초 물 빼기 시작 |
| `Draining` | 애니메이션 없이 타이머만 진행 |
| `WetStarchReady` | 아래 건조 틀에 젖은 전분 표시, `[E]`로 틀 꺼내기 |
| `TrayRemoved` | 건조 틀이 빠져 있는 상태. 중복 생성과 추가 배치 시작 방지 |

체 통의 `1/5`~`5/5` 상태는 이번 테스트에서 Console 로그로 확인한다. 메시, 셰이더, 단계별 내용물 비주얼은 연결하지 않는다.

### 4.3 건조 틀

```csharp
public enum DryingTrayState
{
    InstalledWet,
    CarriedWet,
    Drying,
    Dried,
    CarriedDried,
    Empty
}
```

기본 동작:

1. `InstalledWet`에서 `[E]`를 누르면 플레이어가 틀을 통째로 든다.
2. `OutdoorDryingSurface`로 표시된 실외 바닥을 조준하고 `[E]`를 누르면 조준한 지면 위치에 틀을 내려놓는다.
3. 실외 바닥에 놓인 동안만 150초 건조 시간이 누적된다.
4. 건조 중인 틀을 조준하면 `건조 중 02:14`처럼 남은 시간을 표시하고, Console에는 정해진 간격으로 진행 로그를 출력한다.
5. 150초가 지나면 애니메이션이나 완성 비주얼 없이 `Dried`로 전환한다.
6. 완료된 틀에 `[E]`를 누르면 실제 아이템 지급 없이 `전분 팩 5개 생성` 로그를 출력한다.
7. 테스트 사이클을 반복할 수 있도록 수거 후 건조 틀과 설비 상태를 초기화한다.

실외 바닥 어디든 놓을 수 있어야 하므로 지정 건조대나 고정 슬롯은 만들지 않는다. 대신 실내외 오판정을 막기 위해 건조 가능한 모든 실외 지면에 `OutdoorDryingSurface` 마커 또는 전용 Layer를 적용한다. 건조 틀을 든 상태에서 해당 지면을 Raycast로 조준하면 충돌 지점에 배치한다. 지형, 메시 바닥 등 표면 종류와 관계없이 마커가 있는 실외 지면이면 허용한다.

테스트 기본안에서는 배치 후 건조 완료 전까지 틀을 다시 들 수 없다. 건조 완료 후 `[E]`로 결과 로그를 확인하면 설비가 다음 사이클을 위해 초기화된다.

## 5. 상호작용 안내 문구

기존 게임은 자유 마우스 커서보다 화면 중앙 시선 Raycast를 사용한다. 따라서 요구사항의 “마우스를 댈 시”는 기본적으로 “화면 중앙 조준점으로 바라볼 시”로 구현한다.

권장 문구:

| 상황 | 표시 문구 |
| --- | --- |
| 빈 믹서기 | `[E] 감자 4개 소비 후 분쇄 (테스트)` |
| 분쇄 중 | `분쇄 중 3초` |
| 분쇄 완료 | `[E] 믹서기 들기` |
| 가득 찬 믹서기로 체 통 조준 | `[E] 간 감자 붓기 (2/5)` |
| 빈 믹서기로 원래 자리 조준 | `[E] 믹서기 내려놓기` |
| 체 통 물 빠짐 중 | `전분 분리 중` |
| 젖은 전분 준비 완료 | `[E] 건조 틀 꺼내기` |
| 젖은 틀로 실외 바닥 조준 | `[E] 건조 틀 놓기` |
| 건조 중 | `건조 중 02:14` |
| 건조 완료 | `[E] 전분 팩 5개 수거 (테스트)` |

현재 `PlayerInteractionController`는 상호작용 가능한 대상을 향할 때만 `CurrentPrompt`를 제공한다. 진행 중 상태도 계속 표시하려면 대상은 유지하되 `CanInteract`만 `false`로 하고, `Prompt`는 상태에 따라 동적으로 반환하도록 구현한다.

## 6. 권장 컴포넌트와 파일 구조

```text
Assets/Scripts/Processing/
├─ PotatoStarchProcessor.cs       전체 공정 규칙과 체 통 상태 조정
├─ StarchBlender.cs               믹서기 상태, 분쇄 시간, 들기/복귀
├─ StarchSieve.cs                 1/5 용량, 붓기, 물 빠짐
├─ StarchDryingTray.cs            운반, 건조 진행률, 완성 상태
├─ OutdoorDryingSurface.cs        실외 바닥 판정용 마커

Assets/Editor/

```

`PotatoStarchProcessor`를 규칙의 단일 소유자로 두고, 각 상호작용 컴포넌트는 자신이 마음대로 수량을 바꾸지 않고 `TryStartGrinding`, `TryPourBatch`, `TryTakeTray`, `TryPlaceTray`, `TryCollectProduct` 같은 메서드를 호출한다.

권장 공개 API 예시:

```csharp
bool TryStartGrinding(PlayerInteractionController player);
bool TryTakeBlender(PlayerInteractionController player);
bool TryPourBatch(PlayerInteractionController player);
bool TryReturnBlender(PlayerInteractionController player);
bool TryTakeWetTray(PlayerInteractionController player);
bool TryPlaceTray(OutdoorDryingSurface surface, Vector3 point, PlayerInteractionController player);
bool TryCollectProduct(PlayerInteractionController player);
```

## 7. 테스트용 자원 처리

이번 단계에서는 실제 인벤토리와 아이템 생성 로직을 연결하지 않는다.

- 빈 믹서기에서 `[E]`를 누르면 감자 보유 여부와 관계없이 분쇄를 시작한다.
- 시작 순간 실제 차감 대신 `감자 4개 소비` 로그를 출력한다.
- 완성된 건조 틀에서 `[E]`를 누르면 실제 전분 팩을 생성하거나 지급하지 않는다.
- 수거 순간 `전분 팩 5개 생성` 로그를 출력한다.
- 판매 가격과 판매 로직은 미정이며 이번 범위에서 제외한다.
- 추후 정식 구현에서는 로그가 출력되는 두 지점을 각각 인벤토리의 감자 차감과 전분 팩 지급 API로 교체한다.

## 8. Console 로그 규칙

애니메이션과 결과물 비주얼 대신 모든 입력, 성공한 상태 전환, 실패 이유, 타이머 완료를 Console에서 확인할 수 있게 한다. 로그 접두사는 검색하기 쉽도록 모두 `[PotatoStarch]`로 통일한다.

정상적인 1회 생산 로그 예시:

```text
[PotatoStarch] 감자 4개 소비(테스트). 믹서기 가동 시작. 남은 시간=5초
[PotatoStarch] 믹서기 가동 끝. 감자가 갈아진 상태
[PotatoStarch] 믹서기 들기 완료. 상태=갈린 감자 4개
[PotatoStarch] 체 통에 갈린 감자 투입 완료. 용량=1/5
[PotatoStarch] 빈 믹서기 원위치 완료
```

위 로그가 다섯 번 반복되며 체 통 투입량은 `1/5`부터 `5/5`까지 증가한다. 다섯 번째 투입 이후에는 다음 로그가 이어진다.

```text
[PotatoStarch] 체 통 용량=5/5. 물 빼기 시작. 남은 시간=5초
[PotatoStarch] 물 빼기 완료. 젖은 전분이 건조 틀에 준비됨
[PotatoStarch] 젖은 전분 건조 틀 꺼내기 완료
[PotatoStarch] 건조 틀을 실외 바닥에 배치. 건조 시작. 남은 시간=150초
[PotatoStarch] 건조 진행. 경과=30/150초, 남은 시간=120초
[PotatoStarch] 건조 진행. 경과=60/150초, 남은 시간=90초
[PotatoStarch] 건조 진행. 경과=90/150초, 남은 시간=60초
[PotatoStarch] 건조 진행. 경과=120/150초, 남은 시간=30초
[PotatoStarch] 건조 완료. 전분 팩 5개 준비됨
[PotatoStarch] 전분 팩 5개 생성(테스트). 실제 인벤토리 지급 없음
[PotatoStarch] 가공 설비가 다음 테스트 사이클을 위해 초기화됨
```

프레임마다 로그를 출력하지 않는다. 건조 진행 로그는 기본 30초 간격으로만 출력하며, 상태가 바뀔 때는 즉시 한 번 출력한다. 실패한 상호작용도 원인을 한 번 출력한다.

```text
[PotatoStarch] 믹서기 들기 실패: 아직 분쇄 중. 남은 시간=3.2초
[PotatoStarch] 체 통 투입 실패: 들고 있는 믹서기가 비어 있음
[PotatoStarch] 건조 틀 배치 실패: 실외 바닥이 아님
[PotatoStarch] 건조 틀 꺼내기 실패: 물 빼기가 완료되지 않음
```

## 9. 애니메이션과 프랍 범위

- 이번 테스트에서는 Animator, Animation Clip, Animation Event를 만들거나 연결하지 않는다.
- 분쇄 5초, 물 빼기 5초, 건조 150초는 상태 타이머로만 처리한다.
- 체 통 용량, 젖은 전분, 마른 전분, 전분 팩의 시각 변화는 만들지 않는다.
- `Assets/Fbx/Food Processing`의 프랍은 수정하거나 구조를 분석하지 않는다.
- 이후 아트 연결 단계에서도 게임 규칙은 타이머와 상태 기계가 담당하고 애니메이션은 그 상태를 표현하는 역할만 맡는다.

## 10. 이번 테스트에서 제외하는 항목

- 실제 감자 인벤토리 확인 및 차감
- 실제 전분 팩 생성 및 인벤토리 지급
- 판매 가격과 판매 시스템 연결
- 프랍 세팅, 메시 교체, 애니메이션, 사운드, 파티클
- 가공 상태 저장/불러오기
- 멀티플레이 상태 동기화와 서버 권한 처리
- 날씨, 햇빛, 낮/밤에 따른 건조 조건

정식 구현으로 확장할 때도 현재 상태 변경 API를 유지하고 Console 로그가 출력되는 위치에 실제 시스템 호출을 연결한다.

## 11. 구현 순서

1. `PotatoStarchProcessor` 상태 기계와 5초/5초/150초 타이머를 구현한다.
2. 믹서기 `[E]` 분쇄, 완료, 들기, 붓기, 복귀 흐름을 연결한다.
3. 체 통 `1/5`~`5/5`와 5초 물 빼기 상태를 연결한다.
4. 건조 틀 꺼내기와 손 슬롯 운반을 연결한다.
5. 실외 바닥에 `OutdoorDryingSurface`를 적용하고 조준 위치 배치를 연결한다.
6. 실외 배치 후 150초 건조와 전분 팩 5개 완료 상태를 연결한다.
7. 모든 성공·실패·타이머 전환 Console 로그를 추가한다.
8. 상황별 `[E]` 프롬프트와 외곽선을 연결한다.
9. Editor 자동 검증과 실제 씬 플레이 테스트를 수행한다.

## 12. 자동 검증 항목

`Tools > Project Potato > Validate Potato Starch Processing` 메뉴에서 최소 다음을 검사한다.

- 실제 인벤토리가 없어도 분쇄 시작 성공 및 감자 4개 소비 로그 출력.
- 분쇄 시작 후 4.9초에는 진행 중, 5초에는 완료.
- 분쇄 중 재상호작용 차단과 실패 이유 로그 출력.
- 분쇄 종료 전 들기 실패, 종료 후 들기 성공.
- 가득 찬 믹서기만 체 통에 부을 수 있음.
- 1회 붓기에 정확히 `1/5`만 증가하고 같은 내용물을 두 번 붓지 못함.
- 5회 투입 후 정확히 `5/5`가 되고 `6/5`가 되지 않음.
- 물 빼기 시작 후 4.9초에는 진행 중, 5초에는 젖은 전분 준비 완료.
- 물 빼기 완료 전에 건조 틀을 꺼낼 수 없음.
- 실내 바닥에는 건조 틀을 배치할 수 없고 실패 로그 출력.
- 서로 다른 `OutdoorDryingSurface` 위치 어디에든 배치 가능.
- 실외에서 149.9초에는 미완료, 150초에는 완료.
- 완료 시 전분 팩 수량이 정확히 5개로 기록되고 완료 로그 출력.
- 완료품을 두 번 수거하거나 두 번 생성하지 못함.
- `WorldClock` 일시정지, 배속, `AdvanceBy` 후 상태와 로그가 올바름.

## 13. 플레이 테스트 완료 조건

- 실제 감자 아이템 없이 `[E]` 상호작용만으로 전분 완성까지 한 사이클을 수행할 수 있다.
- 분쇄 5회에 대한 감자 소비 로그가 총 5번 출력되어 가상 감자 소비량 20개를 확인할 수 있다.
- 체 통 용량이 Console에서 `1/5`부터 `5/5`까지 순서대로 출력된다.
- 분쇄 25초, 물 빼기 5초, 건조 150초가 적용된다.
- 건조 틀을 표시된 실외 바닥의 원하는 위치에 놓을 수 있다.
- 모든 성공한 상태 전환과 실패한 상호작용의 이유를 Console에서 확인할 수 있다.
- 완료 시 `전분 팩 5개 생성(테스트)` 로그가 정확히 한 번 출력된다.
- 수거 후 설비가 다음 테스트 사이클을 시작할 수 있는 상태로 돌아온다.

## 14. 확정된 테스트 기본안

- 건조 틀은 실외 바닥에 배치한 뒤 건조 완료 전까지 다시 들 수 없다.
- 건조 틀이 밖에 있는 동안 다음 생산 사이클은 시작할 수 없다.
- 실외 바닥에 놓이면 낮/밤과 날씨에 관계없이 건조된다.
- 건조 완료 후 `[E]`를 누르면 전분 팩 5개 생성 로그를 출력하고 설비를 초기화한다.
- 실제 판매, 저장, 멀티플레이는 이번 테스트에서 제외한다.

이 기본안으로는 테스트 구현을 시작하는 데 추가로 필요한 필수 정보가 없다. 판매 가격이나 정식 인벤토리 API가 정해지면 별도 연결 단계에서 반영한다.
