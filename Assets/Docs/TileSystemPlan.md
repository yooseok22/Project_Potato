# 배열 + 청크 메시 타일 시스템

## 현재 상태

2026-09-18 사용자 요청에 따라 `Assets/Fbx/Tile/Cube.571.prefab`을 반영하고, 개별 타일 프리팹 생성 방식에서 청크 메시 방식으로 전환했다. 이전에 추가 프리팹을 기다리며 보류했던 작업은 실행했다.

- 적용 씬: `Assets/Scenes/YoungSeok/YoungSeok.unity`.
- 타일 구역: 원점 `(-50, 0, -50)`, 50×50칸, 한 칸 2m.
- 청크 크기: 16×16칸. 가장자리의 작은 청크를 포함해 총 16개.
- 런타임 표시: `Ground/GroundChunks` 아래 16개 청크 GameObject와 각각의 MeshFilter·MeshRenderer·MeshCollider. 칸별 프리팹 인스턴스는 생성하지 않는다.
- 구역 인식: 바닥 콜라이더 크기 대신 미리 지정한 구역과 배열 좌표를 사용한다.
- 입력: 커서가 잠긴 게임 화면에서 오른쪽 클릭은 파기, 왼쪽 클릭은 덮기다. 두 작업 모두 거리 제한은 4m다.
- 이전에 방향을 꺾는 파기를 막던 외형 제한은 제거했다.

## 데이터, 선택, 표시의 역할

`GroundGrid`는 명시적인 구역 설정과 칸별 파진 상태·작업 금지 상태 배열을 관리한다. 표시 메시가 바뀌어도 좌표 원점과 크기는 변하지 않는다. 배열 좌표 `Vector2Int.x/y`는 각각 월드 X/Z에 대응한다.

`FarmingTargetSelector`는 카메라 중앙 레이를 기준 높이의 수학적 평면과 교차시켜 칸을 선택한다. 배열 범위, 장애물, 거리와 칸 상태를 검사한다. `FarmingPreviewView`는 칸 중심에 사각형을 표시하고, 작업 가능은 초록색, 불가는 빨간색으로 보여준다.

`GroundTileRenderer`는 배열 상태를 읽어 청크 메시를 구성한다. 프리팹은 메시와 재질의 원본이며, 프리팹의 저장된 월드 위치나 루트 회전은 배치에 사용하지 않는다. 현재 씬에서는 TileMap 빈 오브젝트가 맵을 관리한다. 청크마다 이동용 MeshCollider를 생성하고, 파기 시 변경 청크의 충돌 표면도 표시 메시와 동일하게 갱신한다. 기존 평면 바닥 콜라이더는 사용하지 않는다.

## 원본 메시와 경계 조합

| 원본 프리팹 | 역할 | 원본 메시의 방향 |
| --- | --- | --- |
| `FBX_Land Tile v.1-001` | 기본 땅 | 평면 |
| `FBX_Land Tile v.1-002` | 대각선 외곽 모서리 | -X, -Z 쪽 모서리가 내려감 |
| `FBX_Land Tile v.1-003` | 한 면 경계 | -X 쪽 면이 내려감 |
| `FBX_Land Tile v.1-004` | 파진 땅 | 낮아진 평면 |
| `Cube.571` | 두 면 경계의 안쪽 모서리 | +X, -Z 쪽 두 면이 내려감 |

다섯 메시의 XZ 폭은 2m다. `Cube.571`의 저장된 루트 회전은 180도지만 규칙은 원본 메시의 방향을 기준으로 회전을 지정한다.

하나의 칸을 SW/NW/NE/SE 네 구역으로 나누고 각 구역에 접하는 두 면과 대각선의 파진 상태를 읽는다.

1. 자기 칸이 파졌으면 004.
2. 두 면이 모두 파졌으면 회전한 `Cube.571`.
3. 한 면만 파졌으면 회전한 003.
4. 두 면은 미파진 상태이고 대각선만 파졌으면 회전한 002.
5. 모두 미파진 상태이면 001.

`TileMeshPatch`는 원본 메시의 삼각형을 칸 중심의 X/Z 평면으로 잘라 네 구역의 조각을 만든다. 잘린 점의 UV와 법선은 보간하고, 원본의 서브메시별 재질을 유지한다. 같은 종류·회전·구역의 조각은 최초 생성 시 캐시한다. 조각별 GameObject를 만들지 않고 최종 청크 메시의 정점과 삼각형에 직접 합친다.

이 조합으로 복수 면, 여러 대각선, L자 연결, 마주 보는 구멍 등의 이웃 패턴을 표현한다. 주변 8칸의 256가지 상태에 대한 외형 규칙을 지원한다. 002·003·Cube.571이 포함된 칸도 실제 데이터는 미파진 상태이며 다음 파기 대상으로 선택할 수 있다.

## 파기와 청크 갱신 흐름

```text
오른쪽 클릭
→ FarmingTargetSelector.TryDigSelected()에서 선택·거리 재검사
→ GroundGrid.TryDig()에서 유효 범위·작업 금지·이미 파진 상태 검사
→ 선택 칸의 배열 상태 변경
→ CellChanged 이벤트
→ GroundTileRenderer가 선택 칸과 주변 8칸의 외형 계산
→ 외형이 바뀐 칸이 속한 청크 좌표를 중복 제거
→ 해당 청크만 메시 재생성
```

첫 단일 파기는 9칸의 외형이 바뀌며, 바로 옆을 이어 파면 6칸의 외형이 바뀐다. 숫자를 고정한 처리가 아니라 네 구역의 표시 구성이 달라졌는지를 비교한다. 다른 구멍 근처나 맵 가장자리에서는 변경 수가 달라질 수 있다.

청크 내부에서 파면 보통 하나의 청크를 갱신한다. 청크 경계를 건드리면 이웃 청크도 갱신하고, 네 청크가 만나는 모서리에서는 최대 네 청크를 갱신한다. 바뀌지 않은 청크의 메시와 GameObject는 유지한다.

청크 메시에는 원본 재질별 서브메시가 들어간다. 표시 오브젝트가 16개라는 것은 드로콜이 항상 16회라는 뜻은 아니며, 재질과 그림자 패스에 따른 추가 렌더링이 있을 수 있다.

## 설정 및 파일

`Ground`의 `GroundGrid` Inspector에서 원점, 가로·세로 칸 수와 칸 크기를 설정한다. 선택된 오브젝트의 노란 Gizmo로 구역을 확인할 수 있다. 첫 버전은 수평 XZ 격자와 회전 없는 바닥을 기준으로 한다.

`GroundTileRenderer`의 다섯 프리팹과 청크 크기를 설정한다. 런타임에 코드로 구역을 다시 설정하려면 `GroundGrid.ConfigureArea()`를 사용한다. 이 함수는 상태를 초기화하고 `AreaChanged` 이벤트로 청크를 다시 생성한다.

| 파일 | 역할 |
| --- | --- |
| `Assets/Scripts/Farming/GroundGrid.cs` | 구역, 배열 상태, 좌표 변환, 상태 변경 이벤트 |
| `Assets/Scripts/Farming/FarmingTargetSelector.cs` | 조준 선택, 거리·장애물 검사, 오른쪽 클릭 |
| `Assets/Scripts/Farming/FarmingPreviewView.cs` | 선택 칸 미리보기 |
| `Assets/Scripts/Farming/GroundDigAction.cs` | 작업 가능 상태 검사 |
| `Assets/Scripts/Farming/TileVisualResolver.cs` | 네 구역별 메시 종류와 회전 계산 |
| `Assets/Scripts/Farming/TileMeshPatch.cs` | 원본 메시 자르기 및 조각 캐시 |
| `Assets/Scripts/Farming/GroundTileRenderer.cs` | 청크 생성, 변경 청크 갱신, 생성 메시 해제 |

런타임에서 원본 정점과 삼각형을 읽으므로 타일 메시를 담은 두 FBX의 Read/Write를 활성화했다. 이 설정은 원본 메시의 CPU 데이터 보관 비용을 늘린다. 추후 원본 조각을 에디터에서 미리 굽는 방식으로 바꾸면 런타임 조각 생성 및 원본 Read/Write 요구를 줄일 수 있다.

## 검증 결과

- Editor C# 컴파일 성공.
- 실제 씬에서 청크 16개 생성, 칸별 타일 인스턴스가 없는 것을 확인.
- 첫 파기 9칸, 인접 파기 6칸 외형 변경 확인.
- L자로 방향을 꺾는 파기 성공 및 `Cube.571` 조각 선택 확인.
- 청크 모서리 파기에서 네 청크 갱신 확인.
- 이미 파진 칸의 재파기 거절 확인.
- 256가지 이웃 상태에서 총 21,760개의 표면·경계 위치를 검사했다. 샘플 위치에서 표면 누락이나 겹친 높이 차이가 없었고, 인접 칸 경계 높이가 허용 오차 내에서 일치했다.
- Game 화면에서 파진 땅, 경계와 미리보기 표시를 확인했다.
- 검증용 파기는 Play 종료와 함께 제거했으며 편집 상태로 돌려놓았다.

## 남아 있는 범위와 성능 판단

청크별 MeshCollider로 파진 깊이에 맞춘 이동 충돌을 구현했다. 저장/불러오기 및 멀티플레이 상태 동기화는 아직 구현하지 않았다.

16×16 청크는 초기 설정이며 최적 성능을 확정한 수치는 아니다. 변경 청크의 전체 메시를 재구성하므로, 앞으로 맵 규모와 파기 빈도에 맞춰 생성 시간·갱신 시간·메모리·렌더링 비용을 측정해 조정한다.

기존 `com.unity.ide.visualstudio` 패키지의 초기화 예외가 콘솔에 남아 있다. 타일 스크립트의 컴파일과 위 실행 검증은 통과했으며 해당 패키지 오류는 이번 범위에서 변경하지 않았다.

## 파진 높이의 물리 처리 (추가 적용)

- 청크마다 비볼록·비트리거 MeshCollider 하나를 생성하고, 청크의 렌더링 Mesh를 충돌에도 사용한다. 청크에는 Rigidbody를 추가하지 않는다.
- 파기 시 실제 변경 청크만 메시를 갱신하고 충돌 형상을 다시 굽는다. 매 프레임 갱신하지 않는다.
- 청크는 TileMap의 레이어를 사용한다. Physics 레이어 충돌 설정에서 플레이어와의 충돌이 허용되어야 한다.
- 별도의 기존 평면 콜라이더나 맵 전체 BoxCollider가 활성화되어 있으면 파진 표면을 덮으므로 사용하지 않는다. 현재 확인한 씬에는 해당 평면 콜라이더가 없다.
- Editor 컴파일 통과. 실행 중 16개 충돌 청크를 확인하고, 실제 플레이어 CharacterController가 기본 표면에서 접지한 후 자신의 칸을 파면 약 0.286m 내려가 다시 접지하는 것을 검증했다.
- 청크 모서리의 파기에서 네 청크가 갱신되고 각 MeshCollider와 MeshFilter의 공유 Mesh가 동일함을 확인했다. 테스트 후 Play를 종료했다.

표시 메시를 그대로 충돌에 사용하므로 정확한 표면 높이를 얻는 대신 메시 갱신 시 PhysX cooking 비용이 추가된다. 향후 지형 규모나 연속 파기 빈도가 커지면 해당 비용을 측정한 뒤 충돌 전용 단순 메시 또는 작업 묶음 처리를 검토한다.

## 왼쪽 클릭으로 땅 덮기 (추가 적용)

- 오른쪽 클릭은 기존 파기를 유지하고, 왼쪽 클릭은 선택한 파진 칸을 덮는다.
- GroundGrid의 CanFill/TryFill이 범위·파진 상태·작업 금지를 검사한다. FarmingTargetSelector의 TryFillSelected는 선택·장애물·거리를 다시 검사하고 작업한다.
- 덮은 칸은 미파진 상태가 되고 CellChanged 이벤트로 주변 8칸의 표시와 관련 청크 MeshCollider를 함께 갱신한다.
- 주변에 파진 칸이 없으면 001로 완전히 돌아간다. 파진 이웃이 남으면 그에 맞는 경계가 유지된다. 무조건 001로 강제하면 이웃 구멍의 경계가 끊기므로 배열 상태에서 외형을 계산한다.
- 미리보기는 파기 또는 덮기가 가능한 칸에서 초록색이며, 거리 밖이나 작업 금지 칸은 빨간색이다.
- Esc 이후 커서를 다시 잠그는 첫 왼쪽 클릭은 커서 잠금만 수행한다. ThirdPersonPlayerController.CursorCapturedThisFrame으로 도구 입력과 구분한다.
- 컴파일 통과. 실행 검증에서 단일 구멍 덮기 9칸, 인접 구멍 중 하나 덮기 6칸 변경과 남은 구멍 경계 유지, 청크 모서리의 4청크 갱신을 확인했다.
- selector의 CanFarm/CanFill 전환과 덮기 실행, 범위 밖·거리 밖·작업 금지·이미 덮인 칸의 작업 거절을 검증했다. 충돌 높이가 Y=0으로 복구되었고, 플레이어 발밑을 덮는 경우에도 약 0.286m 올라가 다시 접지했다.
- 테스트 후 Play를 종료했다.
