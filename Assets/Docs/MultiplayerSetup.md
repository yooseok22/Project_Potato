# 멀티플레이 초기 설정

## 시작 씬과 연결

- `Assets/Scenes/MultiplayerMenu.unity`에서 실행합니다. 빌드 씬 목록의 첫 씬입니다.
- NGO + Unity Multiplayer Services API로 Client Hosted 세션을 생성합니다. 호스트 포함 최대 4명, 코드로만 참여하는 비공개 세션입니다.
- CREATE SESSION → 익명 인증 → 세션 코드 생성 → NGO로 MultiplayerGame 씬 로드.
- JOIN SESSION → 입력값 정리 및 코드 참여 → NGO가 호스트의 씬을 동기화합니다.
- 빈 입력은 접속 버튼 비활성화, 연결 작업 중에는 생성/입력/참여를 잠가 중복 요청을 방지합니다.
- 코드 확인/복사, 상태/오류 표시, 나가기와 메뉴 복귀를 제공합니다. 호스트 이전/재연결은 이번 범위에 포함하지 않습니다. 호스트가 종료하면 클라이언트는 메뉴로 돌아옵니다.

## 플레이어 프리팹 연결 위치

1. 메뉴 씬의 `MultiplayerRoot`를 선택합니다.
2. **Multiplayer Session Controller → Player Prefab**에 프리팹을 지정합니다.
3. 프리팹 루트에는 `NetworkObject`가 필요합니다. 모든 실행 인스턴스에 동일한 프리팹을 사용합니다.
4. **NetworkManager의 Player Prefab은 비워 둡니다.** 자동 생성 대신 컨트롤러가 씬 동기화 후 생성하며, 지정된 프리팹은 실행 전 네트워크 프리팹으로 등록합니다.
5. 프리팹의 위치/회전 동기화와 소유자만 입력·카메라를 처리하는 동작은 프리팹 쪽에 추가해야 합니다. 기존 ThirdPersonPlayerController는 로컬 입력용이므로 그대로 모든 네트워크 플레이어에 활성화하면 안 됩니다.

프리팹을 비워 두어도 세션 접속과 씬 이동을 테스트할 수 있습니다. 임시 플레이어는 생성하지 않습니다.

## 인게임 씬

- 충돌 가능한 20 × 20 바닥, 기본 조명과 확인용 카메라.
- SpawnPoints 아래 SpawnPoint_1~4: (-3, 0.1, -3), (3, 0.1, -3), (-3, 0.1, 3), (3, 0.1, 3).
- 스폰 위치/높이/회전은 플레이어 피벗에 맞춰 Inspector에서 조절합니다.
- 서버가 빈 슬롯을 할당하고 연결 종료 시 반환합니다. 늦게 합류한 클라이언트도 씬 동기화 완료 후 생성합니다.
- 다른 씬 작업 중 열려 있던 미저장 씬은 `Assets/Scenes/UntitledBeforeMultiplayer.unity`에 보존했습니다.

## 검증 및 다음 테스트

현재 Editor에서 컴파일, 코드 입력/삭제 시 버튼 활성화, 실제 클라우드 세션 생성 및 코드 발급, 인게임 전환, 네 개의 스폰 위치, 나가기/메뉴 복귀를 확인했습니다. 잘못된 코드 요청은 오류 표시 후 다시 입력 가능한 상태로 돌아갑니다.

아직 별도 클라이언트 간 접속과 실제 플레이어 프리팹의 생성·이동 동기화는 검증하지 않았습니다. 프리팹 연결 후 별도 인증 사용자로 실행되는 에디터/빌드 또는 Multiplayer Play Mode에서 4인 합류, 5번째 참여 거절, 중도 합류, 클라이언트 이탈 후 재참여, 호스트 종료를 확인하세요.

프로젝트는 이미 Unity Cloud 프로젝트에 연결되어 있습니다. 설치되어 있던 Vivox 패키지에는 서버 설정이 없어 서비스 초기화 중 오류 로그가 발생합니다. 현재 세션 생성은 성공했으나 Editor의 Error Pause가 켜져 있으면 일시 정지될 수 있습니다. 음성 채팅 설정은 별도 작업입니다. 기존 Visual Studio Editor 패키지의 코드 리로드 오류도 이번 스크립트의 컴파일 오류와 별개입니다.

UI 확장 제안: 다음 단계에서 참가 인원 표시와 호스트의 게임 시작/준비 버튼을 추가하면 대기실 흐름으로 확장할 수 있습니다.
